# ATS 语法参考

ATS（Automatic-Task Script）是 Automatic-Task 的任务脚本语言，描述任务的执行流程：声明入参、定义步骤、处理分支。一份 `.ats` 文件由**变量声明**、**执行步骤**和**分支控制**三部分组成。

## 文件结构

一份 `.ats` 文件以变量声明开头，接着以 `[Start]` 和 `[End]` 包裹步骤序列：

```text
@var name: string = "World"

[Start]
-> [Script(`echo Hello ${name}`)]
[End]
```

`[Start]` 和 `[End]` 各自只能出现一次。

## 注释

以 `#` 开头至行尾的内容是注释。注释分两种：

```text
# 这一整行都是注释，完全被忽略
@var city: string = "北京"   # 行尾注释——跟在 @var 声明后面时，就是该参数的说明
```

只有跟在 `@var` 声明**同一行**末尾的注释才会被当作参数说明，在 TUI 配置界面选中该参数时显示。独立成行的注释永远只是注释。

## 变量

任务通过 `@var` 声明入参，用户在安装后通过 TUI 或 CLI 配置这些参数的值。

### 语法

```
@var 名称: 类型 [!] [= 默认值] [# 说明]
```

- **名称**：`[a-zA-Z_][a-zA-Z0-9_]*`，不能与关键字重名（`Start`、`End`、`Select`、`Success`、`Failure`、`Default`、`Case`），也不能与[内置变量](#内置变量)重名
- **`!`**：标记为必填。必填变量没有默认值且用户未配置时，运行前校验会报错
- **`= 默认值`**：安装后无需配置即可运行
- **行尾 `#` 注释**：该参数的说明，TUI 配置界面直接展示；不写则自动展示类型与默认值

### 类型

| 类型                | 值域             | 默认值                                 | 说明                                                |
| ------------------- | ---------------- | -------------------------------------- | --------------------------------------------------- |
| `string`            | 任意字符串       | 必填                                   | 单行文本                                            |
| `text`              | 任意字符串       | 必填                                   | 长文本（与 `string` 运行时无差异，UI 上可区分）     |
| `password`          | 任意字符串       | 必填                                   | 密码。日志、事件、运行元数据中脱敏为 `****`，不回显 |
| `number`            | 数字             | 必填                                   | 算术比较和数值运算                                  |
| `boolean`           | `true` / `false` | 必填                                   | 逻辑条件                                            |
| `path`              | 路径字符串       | 必填                                   | 文件系统路径                                        |
| `select("A","B",…)` | 选项之一         | 必填（除非指定了默认值且该值在选项内） | 枚举选择                                            |

### 示例

```text
@var city: string = "北京"                      # 要生成日报的城市
@var depth: select("简版", "详细") = "简版"      # 日报详细程度
@var token: password!                           # 抓取接口的访问令牌
@var retries: number = 3
@var quiet: boolean = false
@var workdir: path = "./output"
```

### 内置变量

以下变量由运行时自动提供，**不需要也不允许**用 `@var` 声明（重名会在校验阶段报错），在模板里直接引用即可。它们的值在一次运行内恒定不变。

| 变量               | 类型     | 含义                                                                      |
| ------------------ | -------- | ------------------------------------------------------------------------- |
| `${Workspace_Dir}` | `path`   | 本次运行的工作区目录。也是所有步骤子进程的工作目录（cwd）                 |
| `${Package_Dir}`   | `path`   | 任务包的解压目录。读取包内自带的文件（脚本、模板、配置）时用它            |
| `${Run_Id}`        | `string` | 本次运行的 ID                                                             |
| `${Task_Id}`       | `string` | 任务 ID                                                                   |
| `${Trigger_Type}`  | `string` | 触发方式：`manual`（手动）或 `schedule`（定时）                           |

`Workspace_Dir` 和 `Package_Dir` 是两个不同的目录：步骤跑在工作区里，产出物写在工作区；任务包自带的文件在包目录里，只读。

```text
[Start]

# 让 agent 明确把产物写到工作区，而不是它自己猜的某个路径
-> [Agent(`读取 ${Package_Dir}/prompts/daily.md，生成日报写入 ${Workspace_Dir}/report.md`)]

# 定时触发时才推送
-> [Select]

    -> [Case(${Trigger_Type} == "schedule")]
        -> [Script(`bash notify.sh ${Run_Id}`)]

    -> [Default]
        -> [Script(`echo 手动运行，跳过推送`)]

[End]
```

## 步骤

步骤按 `-> [类型(参数...)]` 的格式书写，从 `[Start]` 后开始顺序执行。共有三种步骤类型。

### Script

执行命令或脚本。

```
-> [Script(`命令`)]
-> [Script(`命令`, timeout: 秒)]
```

命令文本支持[模板](#模板)变量替换。如果命令是相对路径（如 `scripts/run.sh`），会相对于**任务包的解压目录**解析。`.bat` 和 `.cmd` 文件会经由 `cmd /d /s /c` 执行，其它命令直接 spawn。

```text
-> [Script(`node -e "console.log('Hello')"`)]
-> [Script(`scripts/fetch.sh ${city}`)]
-> [Script(`python heavy-job.py`, timeout: 3600)]
```

### Agent

调用外部 AI Agent CLI 工具。

```
-> [Agent(`提示词`)]
-> [Agent(`提示词`, timeout: 秒)]
```

提示词支持[模板](#模板)变量替换。运行时将提示词作为最后一个参数传给 Agent 命令。

Agent 命令在全局设置中配置：

| 配置项 | 默认值 | 说明                                     |
| ------ | ------ | ---------------------------------------- |
| 命令   | `pi`   | Agent CLI 工具，如 `pi`、`claude` 等     |
| 参数   | （空） | 传给 CLI 的固定参数                      |
| 模型   | （空） | `-m <模型>`，不填则用 CLI 自己的默认模型 |

实际执行的命令行等价于：

```
<命令> <参数...> [-m <模型>] <提示词>
```

```text
-> [Agent(`为 ${city} 生成日报，写入 report.md`, timeout: 120)]
-> [Agent(`总结本次失败的日志并给出修复建议`)]
```

### Docker

在容器中运行镜像。

```
-> [Docker(`镜像`)]
-> [Docker(`镜像`, `命令`)]
-> [Docker(`镜像`, `命令`, timeout: 秒)]
-> [Docker(`镜像`, `命令`, timeout: 秒, remove: false)]
```

镜像和命令文本均支持[模板](#模板)变量替换。Docker 步骤自动完成以下工作：

- 宿主 workspace 目录挂载到容器的 `/workspace`，并设为工作目录
- 默认启用 `--rm`（容器退出后自动删除）

| 参数             | 类型 | 默认值 | 说明                   |
| ---------------- | ---- | ------ | ---------------------- |
| `镜像`（位置 1） | 模板 | 必填   | Docker 镜像名          |
| `命令`（位置 2） | 模板 | 可选   | 容器内执行的命令       |
| `timeout:`       | 数字 | 无限制 | 超时秒数               |
| `remove:`        | 布尔 | `true` | 容器退出后是否自动删除 |

```text
-> [Docker(`python:3.12`, `python /workspace/process.py`)]
-> [Docker(`ubuntu`, timeout: 600)]
-> [Docker(`node:20`, `npm test`, timeout: 300, remove: false)]
```

### 公共约束

- 每个步骤至少需要一个位置参数（命令/提示词/镜像）
- `timeout` 可以写**正数字面量**，也可以写**单个 `number` 类型变量**的引用，例如 `timeout: ${seconds}`
- 步骤按书写顺序执行，失败/超时/取消不会中断链路——后续的 `[Select]` 的 `[Failure]` 分支可以响应

## 模板

反引号（`` ` ``）字符串就是模板，运行时用变量值替换其中的 `${变量名}` 占位符：

```text
`为 ${city} 生成${depth}日报`
```

- 变量名只允许 `[a-zA-Z_][a-zA-Z0-9_]*`
- 变量必须已通过 `@var` 声明
- `${}` 内部为空会报错
- 替换结果永远是字符串——数字变量在 `${n}` 中会转成字符串，布尔变量在 `${flag}` 中变成 `"true"` / `"false"`

模板可以用在：

| 位置             | 示例                             |
| ---------------- | -------------------------------- |
| Script 命令      | ``Script(`echo ${name}`)``       |
| Agent 提示词     | ``Agent(`为 ${city} 生成日报`)`` |
| Docker 镜像/命令 | ``Docker(`${image}`)``           |
| Case 条件        | `[Case(${depth} == "详细")]`     |
| timeout 参数     | ``Agent(`x`, timeout: ${secs})`` |

`timeout:` 的写法比其它位置严格：只接受**单个变量引用**，且该变量必须声明为 `number`。混入其它文本（如 `` timeout: `${secs}0` ``）或引用非数字变量都会在校验期报错。

### 变量值与命令行参数

命令行按脚本里写死的空格切分参数，**变量值整体算一个参数**——值里带空格不会被切开：

```text
@var greeting: string = "hello world"
[Start]
-> [Script(`node print.js ${greeting}`)]
[End]
```

`print.js` 收到的 `argv[2]` 是完整的 `hello world`，不是 `hello`。同理，值里出现的引号也只是普通字符，不会和脚本里的引号配对。

## Select 分支

`[Select]` 根据上一步的执行结果或条件表达式，选择**第一个匹配**的分支执行。不匹配时跳过整个 `[Select]`，链路随之终止。

### 分支类型

按优先级从高到低：

```text
[Select]
    -> [Success]        # 上一步成功（含尚无前序步骤的情况）
        -> …

    -> [Failure]        # 上一步失败、超时或取消
        -> …

    -> [Case(条件)]     # 条件表达式为真
        -> …

    -> [Default]        # 以上都不匹配时执行
        -> …
```

每种分支在一个 `[Select]` 内最多出现一次。

### 分支匹配规则

1. 按声明顺序检查，执行第一个匹配的分支
2. `[Case]` 的条件是[表达式](#表达式)，结果换算为布尔值
3. `[Success]` 在没有前序步骤时也算成功（允许 `Start → Select → Success` 这种模式）
4. `[Failure]` 覆盖三种非成功状态：失败、超时、取消
5. 一个分支都不匹配时，`[Select]` 返回 `skipped`，**链路终止**——后续步骤不再执行

### 示例

```text
[Select]
    -> [Case(${depth} == "详细")]
        -> [Script(`generate-detailed.sh`)]

    -> [Case(${depth} == "简版")]
        -> [Script(`generate-brief.sh`)]

    -> [Default]
        -> [Script(`generate-default.sh`)]
```

```text
[Select]
    -> [Failure]
        -> [Script(`notify-failure.sh`)]

    -> [Success]
        -> [Script(`notify-success.sh`)]
```

### 嵌套

`[Select]` 的分支体内可以放任意步骤序列，包括另一个 `[Select]`：

```text
[Select]
    -> [Case(${mode} == "full")]
        -> [Script(`step-a.sh`)]
        -> [Select]
            -> [Failure]
                -> [Script(`fallback.sh`)]
            -> [Default]
                -> [Script(`continue.sh`)]
```

## 表达式

表达式用于 `[Case]` 分支的条件判断，支持比较、逻辑运算和取反。

### 比较运算符

| 运算符 | 说明     |
| ------ | -------- |
| `==`   | 等于     |
| `!=`   | 不等于   |
| `>`    | 大于     |
| `>=`   | 大于等于 |
| `<`    | 小于     |
| `<=`   | 小于等于 |

- `==` 和 `!=` 在所有类型间做**宽松比较**：数字 `5` 和字符串 `"5"` 视为相等，布尔 `true` 和字符串 `"true"` 视为相等
- `>` `>=` `<` `<=` 只适用于数字，两个操作数都转为数字后比较

### 逻辑运算符

| 运算符 | 说明                                 |
| ------ | ------------------------------------ |
| `&&`   | 逻辑与（短路：左侧为假时不求值右侧） |
| `\|\|` | 逻辑或（短路：左侧为真时不求值右侧） |
| `!`    | 逻辑非                               |

### 真值规则

在逻辑运算和分支条件中，值按以下规则换算为布尔：

| 值的类型                   | 视为真的条件                    |
| -------------------------- | ------------------------------- |
| `true`                     | 永远为真                        |
| `false`                    | 永远为假                        |
| 非零数字                   | 真；`0` 为假                    |
| 非空字符串且不是 `"false"` | 真；空串 `""` 和 `"false"` 为假 |

```text
[Case(${retries} > 0 && ${mode} != "off")]
[Case(!${quiet})]
```

### 字面量

表达式中可以直接写数字、字符串、布尔值：

```text
[Case(${count} > 10)]
[Case(${name} == "admin")]
[Case(${enabled} == true)]
```

## 执行模型

### 链路

从 `[Start]` 后的第一个节点开始，按声明顺序逐个执行。节点分两种：

- **步骤**（Script / Agent / Docker）：立即执行
- **Select**：根据上一步的状态和分支条件，选择**第一个**匹配的分支执行

### 中断与继续

| 情况                     | 行为                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| 步骤成功                 | 继续执行下一个节点                                                                |
| 步骤失败 / 超时 / 取消   | **不中断**——继续执行下一个节点，由后续 `[Select]` 的 `[Failure]` 分支决定如何处理 |
| Select 无分支匹配        | 返回 `skipped`，**链路终止**                                                      |
| 用户调用 `autotask stop` | 发送 Abort 信号，**立即终止**链路                                                 |

### 状态传递

每一步的执行结果（成功/失败/超时/取消）会传给下一个节点的 `[Select]`，这就是 `[Success]` 和 `[Failure]` 判断的依据。

上一步的**输出内容和退出码不会**暴露成变量，脚本里读不到。需要在步骤之间传递数据时，写文件到工作区：

```text
[Start]

-> [Script(`bash fetch.sh > ${Workspace_Dir}/data.json`)]
-> [Script(`bash render.sh ${Workspace_Dir}/data.json`)]

[End]
```

所有步骤的 cwd 都是同一个工作区，所以相对路径也可以（`> data.json`）；写成 `${Workspace_Dir}/data.json` 只是更明确，尤其是传给 agent 的提示词里。
